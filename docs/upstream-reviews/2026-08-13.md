## Executive recommendation

Do **not** merge either upstream branch wholesale. Both have changed package/API assumptions, and
pi-observational-memory replaced its persisted memory format entirely. The safest strategy is a
small adapted batch of improvements that does not alter:

- `MemoryDetailsV4` or existing session entries;
- 12-character base-36 memory IDs;
- `hm_recall`'s dual 12-character memory / 8-character source contract;
- the merged OM + VCC summary grammar;
- `firstKeptEntryId` and observation coverage semantics;
- existing `hybrid-memory.*` config keys.

## Recommended compatibility-safe batch

### 1. Observer input budgeting and oversized-entry recovery — merge now

**Source:** pi-observational-memory commits
[`2057c10`](https://github.com/elpapi42/pi-observational-memory/commit/2057c104e9199f15bb92eb706d1214b6ce5f6b72),
[`d0ebd32`](https://github.com/elpapi42/pi-observational-memory/commit/d0ebd32da6444a028b0b5de1fc387de24ad8224a),
[`207da5f`](https://github.com/elpapi42/pi-observational-memory/commit/207da5f89ab9ae3561f6f5018b28dda5445143a8), and
[`3995fbd`](https://github.com/elpapi42/pi-observational-memory/commit/3995fbd0ac906079b6a73cac6d8ae32d0db6637b).

Upstream caps serialized observer input, drains old backlog incrementally, and handles one enormous
source entry by sending a marked head/tail excerpt while retaining the original source ID. The raw
session entry remains unchanged and recallable.

Hybrid currently serializes the full selected tail in
`src/om/serialize.ts::serializeSourceAddressedBranchEntries` and sends it in one observer call from
`src/observer-trigger.ts`. A pathological tool result can therefore overflow or repeatedly stall
the observer.

**Risk:** Low. Add one optional setting and port the algorithm onto hybrid's existing entry and
coverage types. Do not copy the V3 ledger.

### 2. Observer terminal-error detection and deliberate-empty backoff — merge now

**Source:** pi-observational-memory commits
[`036e796`](https://github.com/elpapi42/pi-observational-memory/commit/036e7962a4306fe3c1860aaafea6a250c86009a8) and
[`3995fbd`](https://github.com/elpapi42/pi-observational-memory/commit/3995fbd0ac906079b6a73cac6d8ae32d0db6637b).

`agentLoop` can finish with a terminal assistant event whose stop reason is `error` or `aborted`
without throwing. Hybrid currently drains events without inspecting them in `src/om/observer.ts`,
so such failures may be reported as a legitimate empty observation result. Upstream also backs off
a deliberate empty verdict until enough new source content arrives, preventing repeat calls over
the same span.

**Risk:** Low. No storage or config migration is required.

### 3. Modern file-operation extraction and authoritative `fileOps` — merge now

**Source:** pi-vcc commits
[`2839251`](https://github.com/sting8k/pi-vcc/commit/2839251454b2fe058af1aa5e1da784d63de7cf0b) and
[`88dddd8`](https://github.com/sting8k/pi-vcc/commit/88dddd864a1f38f0e726f35ddd4dc17d870cb46e).

Upstream now matches file tools case-insensitively, recognizes lowercase `read`, `quick_edit`,
`target_edit`, and `apply_patch`, and seeds activity from Pi's authoritative compaction
`preparation.fileOps`.

Hybrid's sets in `src/vcc/extractor.ts` are case-sensitive and omit several modern tools;
`src/compaction-hook.ts` also ignores `preparation.fileOps`. This can silently omit changed files
from `[Files And Changes]`.

**Risk:** Low. The persisted grammar does not change; summaries become more accurate.

### 4. Include `custom_message` and `branch_summary` in the VCC input — merge now

**Source:** pi-vcc commit
[`fdc4c86`](https://github.com/sting8k/pi-vcc/commit/fdc4c86199fab44dfd67c27e5d066d79d0a62313).

Hybrid already understands these entry types in OM serialization, token counting, branch handling,
and recall. Its VCC input in `src/compaction-hook.ts`, however, still selects only normal message
entries. Reusing the existing raw-entry conversion would prevent VCC-side context loss without
changing storage.

**Risk:** Low. Watch for redundant semantic coverage between OM and VCC, but that is a summary-size
concern rather than a compatibility break.

### 5. `bashExecution` normalization — merge now

**Source:** pi-vcc commit
[`fc21aa7`](https://github.com/sting8k/pi-vcc/commit/fc21aa7b259c3662bbae10b441321b70f8bd3636).

Current upstream recognizes Pi `role: "bashExecution"` as a shell-command block. Hybrid currently
captures Bash only when represented as an assistant tool call. Adding a normalized Bash variant
would preserve commands emitted through the newer role.

**Risk:** Low, with focused normalizer/transcript tests.

### 6. Prompt hardening — adapt now

**Source:** pi-observational-memory commits
[`1d9fe89`](https://github.com/elpapi42/pi-observational-memory/commit/1d9fe89d6302bdd217fe97191138cb24e189d0a0),
[`0f170a5`](https://github.com/elpapi42/pi-observational-memory/commit/0f170a58284b67d9c22bf3ef5feb81464cf8103c), and later prompt refinements through
[`e6c0fd9`](https://github.com/elpapi42/pi-observational-memory/commit/e6c0fd9d8e43ffb5d3c1a271bf1ec4a4640bde02).

Useful rules to port:

- preserve authoritative user assertions even if later discussed as questions;
- preserve exact unusual terminology, paths, identifiers, errors, metrics, counts, decisions, and rationale;
- record concrete completions so a future agent does not redo finished work;
- make supersession explicit when new state replaces old state;
- split observations by fact;
- apply a strong reflection abstraction gate so transient task logs remain observations.

**Risk:** Low for persisted compatibility, medium for memory semantics and cost. Port only prompt
rules first; do not simultaneously replace reflector/pruner execution.

### 7. Usable OAuth/header-auth validation — adapt now

**Source:** pi-observational-memory commit
[`2ac0e4f`](https://github.com/elpapi42/pi-observational-memory/commit/2ac0e4f427679320efc7734956621aba2814206c).

Upstream treats either a non-empty API key or at least one non-empty auth header as usable auth.
Hybrid accepts `auth.ok` and forwards headers, which likely works for OAuth, but it does not verify
that either usable credential form is present in `src/runtime.ts::resolveModel`.

**Risk:** Low. Add validation and tests without changing provider configuration.

## Worth adapting later

### Ranked VCC brief and fresh-summary preservation

**Source:** pi-vcc ranking/merge work beginning at
[`75b0bc9`](https://github.com/sting8k/pi-vcc/commit/75b0bc92dd24b8e14ee14c17ceb97b3b005f10ff).

Upstream ranks edits, test/build commands, workflow commands, nonzero exits, nearby context, and
segment-closing assistant reports. It also protects the fresh brief and gives old brief content only
the remaining rolling budget.

Hybrid currently appends old and fresh VCC briefs, then relies on the global merged-summary budget.
Ranking could reduce low-value transcript growth, but it must retain hybrid's thinking and tool-error
blocks and integrate with `maxSummaryTokens` rather than replacing it.

**Risk:** Medium. Adapt selectively with fixture/integration tests.

### Assistant line-break preservation and hardened heredoc rendering

**Source:** pi-vcc commits
[`c2aa274`](https://github.com/sting8k/pi-vcc/commit/c2aa2746e040ad6ea892e099f1557eba46d5daaf) and
[`1881b64`](https://github.com/sting8k/pi-vcc/commit/1881b643341d386193283631f8562f8d1c103dff).

Useful for preserving code blocks and meaningful shell context. Keep this independent from
persisted-summary wrapping.

**Risk:** Low/Medium due summary growth and possible heredoc content exposure.

### Passive mode, notification toggle, and stage diagnostics

Current observational-memory upstream has useful controls, but its config schema was replaced.
Add equivalent behavior only under the existing `hybrid-memory.*` namespace and preserve old keys.

**Risk:** Low/Medium if added as optional settings; critical if upstream config replaces ours.

### Target-based pruning pressure

Upstream separates maximum and target observation-pool sizes and ranks candidates by coverage,
relevance, and age. Hybrid could adopt target-based gating and diagnostics while retaining its own
storage and stronger protection for critical memories.

**Risk:** Medium. Do not adopt tombstones or critical-observation dropping.

### Provider-anchored observer clocks

Upstream uses real provider token growth when a reliable anchor exists and falls back to estimates.
This can improve observer trigger accuracy. Hybrid should retain its user-requested absolute context
percentage for auto-compaction.

**Risk:** Medium because trigger timing changes.

### Separate history/touched-files search

Current pi-vcc supports touched-file indexing and file-scoped drill-down. This is complementary to
`hm_recall`, but should be a separate tool/command rather than changing the established dual-ID
schema. Pass `ctx.cwd` explicitly and enforce current-lineage scope.

**Risk:** Medium public-surface addition; no persisted-schema risk.

## Defer

- Moving reflection/pruning into a unified background consolidation pipeline.
- Converting reflector/pruner from `completeSimple` to tool-calling agent loops.
- Smart keep-tail and token-budget cuts that choose a new `firstKeptEntryId`.
- Invisible automatic continuation after compaction.
- A package/import migration from `@mariozechner/*` to `@earendil-works/*`.

These changes interact with lifecycle APIs, cost, observation coverage, or every SDK import and need
dedicated design and integration testing.

## Reject without an explicit migration

### Observational-memory V3 ledger and `om.folded` details

**Source:** pi-observational-memory commit
[`c94927b`](https://github.com/elpapi42/pi-observational-memory/commit/c94927bb5692c8c82a40f1ac0777459b36703b07).

Upstream replaced baseline observation entries and `MemoryDetailsV4` with an append-only ledger:
`om.observations.recorded`, `om.reflections.recorded`, `om.observations.dropped`, and compaction
`details.type: "om.folded"`. Its V3 reader intentionally ignores old V2 memory. Hybrid sessions use
a different entry type, v4 details, and base-36 IDs.

**Risk:** Critical persisted-session incompatibility. Never cherry-pick this storage layer.

### Render-only OM compaction replacing hybrid compaction

Current observational-memory compaction only renders already-prepared memory and may delegate empty
memory to Pi. Hybrid must also run VCC extraction and merge the two pipelines. Replacing its hook
would remove core functionality.

### Hex-only recall and replacement ID contract

Hybrid's dual 12-character memory / 8-character source lookup is a superset for its own sessions.
Replacing it with upstream's V3 hex-only memory recall would break persisted base-36 IDs and source
lookup.

### Critical-observation dropping and V3 tombstones

Hybrid deliberately protects critical memories. Upstream can drop critical observations when it
considers reflection coverage sufficient, and records tombstones in the V3 ledger. Both the policy
and storage mechanism are incompatible.

### Persisted-summary line wrapping

**Source:** pi-vcc commits
[`ad1fa01`](https://github.com/sting8k/pi-vcc/commit/ad1fa019015f7d6d26726390cc1817be10d487fc) and
[`ab148ae`](https://github.com/sting8k/pi-vcc/commit/ab148ae382f8275508ce588d68e3f46d123ef0e1).

Current pi-vcc wraps all stored lines at 120 characters. Primary-source testing found that wrapped
recall notes are no longer stripped on later compactions and wrapped file lists lose continuation
paths when reparsed. Wrap only in the TUI, never in persisted summary grammar.

### Removing thinking and tool-error normalization

Hybrid retains thinking, error markers, and error-derived outstanding context. Current pi-vcc
removed them. That would reduce debugging and continuity quality.

### Upstream command renames and automatic clipboard writes

Keep `/hm-status`, `/hm-memory`, and `hm_recall`. Automatic clipboard side effects and `/om:*`
command takeover do not improve the hybrid design.

## Already present or redundant

- Hybrid already defaults `overrideDefaultCompaction` to true.
- Hybrid already supports `custom_message` and `branch_summary` in OM and recall paths.
- Hybrid already has stronger missing-`firstKeptEntryId` recovery than either recorded baseline.
- Hybrid already uses `agent_settled` for percentage/token auto-compaction.
- Hybrid recall already provides bounded, fairly distributed previews and direct exact-source lookup.
- Hybrid already retains thinking and tool-error information that current pi-vcc removed.

## Adoption status

Implemented in the VCC accuracy batch on 2026-08-13:

- Modern case-insensitive file-tool matching and `preparation.fileOps` seeding.
- VCC inclusion of `custom_message` and `branch_summary` entries.
- `bashExecution` normalization through the existing bash tool-call/result block model.

Implemented in the observer reliability batch on 2026-08-13:

- Terminal `agentLoop` error/abort detection with partial-observation preservation.
- Deliberate-empty backoff until one additional observation threshold accumulates.
- Bounded oldest-first observer chunks with a 60,000-token default, 256-token safety floor, and oversized single-entry head/tail excerpts.
- Full-gap bounded catch-up before compaction, preserving fail-closed coverage.
- API-key or non-empty auth-header validation for session and configured compaction models.

The persisted summary grammar, memory schemas, IDs, compaction boundaries, thinking blocks, and tool-error handling were unchanged.

Implemented in the prompt-hardening batch on 2026-08-13:

- Authoritative user assertions remain authoritative unless explicitly corrected or superseded.
- Exact terminology, paths, identifiers, errors, metrics, counts, decisions, constraints, completions, and rationale receive explicit preservation guidance.
- Independent facts are split, concrete completions are marked, and repetitive low-information activity is grouped or omitted.
- The reflector applies a strong durable-value/abstraction gate and treats inflated support ids as unsafe for pruning.
- Stable observer instructions precede changing memory and source content to improve prompt-prefix cache reuse where providers support it.

No schemas, storage, ids, pruning rules, compaction boundaries, or recall contracts changed.
